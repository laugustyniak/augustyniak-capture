# Clipboard history

A polled system-clipboard history, reachable as a tab and as a hotkey sheet. Not part of the capture pipeline.

**Clipboard** (`features/clipboard/`) — a system-clipboard history, reachable both as tab 3 and as a hotkey sheet (`Ctrl+Alt+V`). It is **not** part of the capture pipeline and must not become one: an entry stays an entry until the user sends it on, and `TO CAPTURE` hands off through `RecordingsController.addTextNote` / `addImportedFile`, which take the same `_isBusy` lock and run the same verify-then-persist-then-enqueue pipeline as every other capture entry point. There is no second way into the queue.

- **It polls, and there is no alternative.** No platform offers a cross-platform clipboard-change notification, so `ClipboardWatcherService` runs a 750 ms `Timer.periodic` with a `_checkInFlight` single-flight guard. Images are checked first and `return` on a hit, so one copy can never produce both an image row and a text row. On macOS the native side short-circuits on `NSPasteboard.changeCount`, so an idle pasteboard costs the channel hop and nothing else.
- **The service remembers what it last wrote.** `copyToClipboard` sets `_lastText`/`_lastImagePath` **before** writing to the pasteboard, which is the only thing stopping the poller from re-indexing the app's own paste as a brand-new entry — an infinite history from one click. The repository's adjacent-duplicate check is a second net, not the first one.
- `ClipboardGateway` is the seam (`SystemClipboardGateway` in production), same shape as `ClipboardSink`, which is what keeps the watcher pure-Dart testable. **Image support is optional and wrapped in its own `try`**: a platform with no native image bridge answers `MissingPluginException`, and text must still be observed there. `test/clipboard_history_test.dart` pins exactly that.
- **Two `ClipboardRepository` implementations, and the shell wires the SQLite one.** `SqliteClipboardRepository` is production; `LocalJsonClipboardRepository` (`clipboard_history.json`, atomic `.tmp` + `rename`, `.corrupt-<ts>` backup on an unreadable read) is what the tests use and what the legacy migration reads from. Both cap at `maxItems = 100000`, i.e. effectively not at all. **All three ways a row leaves take its PNG with it** — `deleteItem`, `clearHistory` and eviction past the cap — and that file is the one artifact this feature owns. Eviction is the one that has to work for it: the SQLite trim used to be a bare `DELETE ... WHERE id NOT IN (...)`, which drops the only record of where the file was *before* anything can read it, so it has to `SELECT image_path` for the doomed rows first. Nothing sweeps the images directory — there is no `findOrphans` counterpart here — so a stray PNG is a file no code path can ever name again. `test/clipboard_sqlite_test.dart` pins all three, and pins that a file already missing does not fail the operation.
- **Three storage roots, and they do not agree.** The SQLite database is in Application Support; the native `getClipboardHistoryDirectory` (used only by the JSON impl) returns a per-platform `AugustyniakCapture` folder — Application Support on macOS, `filesDir` on Android, an app-group container on iOS; and macOS writes captured images to `~/Documents/AugustyniakCapture/images/clip_<uuid>.png`, i.e. under **documents**, not beside either index. So clearing the history removes the rows and the PNGs it still knows about, and an orphaned PNG from a database that was reset is invisible to every code path. There is no orphan sweep here, unlike the recordings directory.
- **`autoPaste` is macOS-only and needs Accessibility permission.** It hides the app and synthesises `⌘V` through `CGEvent` 120 ms later, into whatever had focus before. Without the permission the keystroke is **silently dropped** — the app hides and nothing is pasted, which reads exactly like a broken button. Android and iOS implement only `getClipboardHistoryDirectory` (iOS from an app-group container), so there is no image capture and no auto-paste there; the sheet's `PASTE` degrades to "copy to the clipboard". **`pasteToActiveApp` awaits its `invokeMethod`, and the `await` is load-bearing** — it is the only thing putting the `MissingPluginException` those platforms raise inside the method's own `try`. Unawaited, the call returned a future nobody held and the error escaped as an unhandled async error while the `catch` sat there looking correct. The regression test wraps the call in `runZonedGuarded` and asserts nothing escapes, because that is the only formulation that fails without the `await`: a plain `await pasteToActiveApp()` passes either way, since an orphaned future reports itself too late for the test that created it.
- **UI is a list beside a preview** (`clipboard_history_sheet.dart`), not a list of expanding rows: fixed 58 px rows on the left, the whole selected entry and *every* action on the right. That is what moved `DELETE` — the one irreversible control here, with no undo and no orphan recovery — away from the tap target that pastes and closes the sheet. Below `Console.compactBreakpoint` the same pane moves under the list, so a phone and a desktop cannot offer different actions.
- The selection is an **id, not an index**, for the same reason the queue's `focusedId` is: a new entry lands at the head of the list every time the user copies anything, and an index would silently move the selection onto it. Arrows move, `Enter` pastes what the pane shows. The other three actions advertise no shortcut on purpose — the search box is autofocused in the sheet, `EditableText` eats anything that could bind to them, and a key hint on a button that cannot fire is indistinguishable from a shortcut the OS refused.
- **`isModal` is not cosmetic.** It gates the drag handle *and* the search box's `autofocus`. Autofocus is right for the hotkey sheet and was a real defect in the tab: the shell keeps all seven tabs alive in an `IndexedStack`, Clipboard is built after the Queue, and the last `autofocus` registered with the route's `FocusScope` wins — so an off-screen search field held the focus `_QueueShortcuts` needs and every queue shortcut (`j`/`k`/`e`/`d`) was dead from launch until the user clicked something.
- `ClipboardItem.preview` still holds `'[Obrazek]'` on rows written before the English-only pass. `docs/superpowers/specs/2026-08-09-english-only-strings-design.md` covers it deliberately as a data question, not a string question — the field is persisted, so translating the literal does not translate what is already on disk.
